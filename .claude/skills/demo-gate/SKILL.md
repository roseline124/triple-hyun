# 시연과 제출 준비 점검

`docs/HACKATHON.md`의 제출 규정과 `docs/PROJECT.md`의 핵심 가치를 읽는다.
현장 운영진 공지로 제출 규정 변경을 확인한다. 남은 자리가 제공되지 않으면 추정하지 않고 확인 필요로 쓴다.

1. 심사자가 사용할 공개 URL을 새 세션에서 연다. 로그인/배포 보호/환경 변수 누락을 확인한다.
2. 대표 입력으로 실제 AI 핵심 처리부터 결과까지 실행한다. 가짜 응답/녹화/fixture는 표시한다.
3. 핵심 시연을 두 번 반복하고, 느린 응답·실패·재시도·새로고침을 확인한다.
4. 프로덕션 빌드, 타입 검사, 린트, 관련 테스트 결과와 미실행 항목을 기록한다.
5. 390px 모바일 웹, 키보드 주요 행동, 로딩·오류·빈 상태를 확인한다.
6. 2장 이하 자료에서 사용자/문제/전후 차이/제품 화면/검증 근거/시장 가설/한계를 확인한다.
7. 90초 시연 대본, 백업 영상/캡처, 샘플 입력, 10분 결선 발표·질의응답 준비를 확인한다.

`artifacts/demo-gate.md`에 항목별 PASS/FAIL/미검증과 증거를 남긴다.
통과 기준은 공개 URL, 실제 핵심 AI 흐름, 핵심 치명 오류 없음, 2장 자료, 재현 가능한 시연이다.
필수 항목 실패 시 막는 오류 하나와 최소 수정 시간을 제시한다. 잔여 자리가 적어도 허위 통과시키지 않는다.
통과 시 현재 시각·남은 자리·치명 위험을 근거로 즉시 제출 또는 짧은 보완을 추천한다.
마지막에 **제출 URL·최종 자료·한 번만 제출 가능함**을 보여주고 사용자 승인을 요청한다.
승인 전 전송하지 않는다. 제출 후 심사 배포본과 제출 기록을 고정한다.
