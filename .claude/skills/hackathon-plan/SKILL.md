# 해커톤 기획

먼저 `AGENTS.md`, `docs/HACKATHON.md`, 기존 코드와 팀 스택을 확인한다.

사용자·고통·왜 지금·가장 작은 유용한 결과·코딩 없이 확인할 방법·제외할 기능을 확인한다.
사용자 입력에 답이 있으면 재질문하지 않는다. 결정에 꼭 필요한 질문 최대 3개를 한 번에 묶는다.
답을 기다리는 동안 독립적으로 확인 가능한 자료·기존 코드를 조사한다.

최대 세 후보를 사용자 접근성, 문제 강도, 90초 시연성, 2시간 내 구현 가능성으로 비교한다.
추천 하나와 탈락 이유를 짧게 제시한다. 점수를 시장 검증으로 오인하지 않는다.
기획 전체는 20분을 넘기지 않도록 타임박스를 알린다.

다음 여섯 항목을 한 페이지 안팎으로 `docs/PROJECT.md`에 정리한다.
1. 문제 정의: 특정 사용자, 현재 대안, 실제 근거와 가정, 왜 지금.
2. 방향 추천: 핵심 가치 한 문장, AI가 꼭 필요한 처리, 코딩 없이 확인할 질문 하나.
3. MVP 범위: 입력 → 실제 Claude 처리 → 관찰 가능한 결과, 화면 최대 3개, 제외 목록.
4. 개발 에이전트 작업: 15~30분 단위, 담당자, 파일, 입출력 계약, 완료 조건, 의존성.
5. 검증 체크리스트: 핵심 성공 경로, 실패/재시도, 배포 URL, 90초 시연, 제출 자료.
6. 위험: 기술·데이터·비용·남은 자리, 대체 시연과 명시적 한계.

제품 방향·스택·새 유료 의존성은 한 번 승인받는다. 승인된 작업은 반복 승인 없이 수행한다.
자동 커밋, 푸시, 최종 제출을 하지 않는다. 새 요구는 기존 핵심 흐름을 대체하거나 후순위 목록으로 보낸다.
작업이 끝나면 `docs/PROJECT.md`에 실제 결과와 다음 작업만 갱신한다.
