# 사업기획과 발표 자료

먼저 `docs/PROJECT.md`, `docs/HACKATHON.md`, 실제 제품과 이용 가능한 증거를 확인한다.
아이디어가 정해지지 않았다면 `hackathon-plan`부터 적용한다. 제품이 없으면 초안으로 표시한다.
출력 형식을 이미 요청했다면 다시 묻지 않는다. 'PPT' 요청은 실제 편집 가능한 `.pptx` 파일을 포함한다.

필요한 역할만 현재 대화에서 순서대로 적용한다. 자동 병렬 에이전트를 만들지 않는다.
- 사업성: `../agency-business-strategist/SKILL.md` → `docs/BUSINESS.md` 한 페이지.
- 문서와 주장: `../agency-proposal-strategist/SKILL.md` → `docs/PITCH.md`의 장별 메시지와 근거.
- 시각 서사: `../agency-visual-storyteller/SKILL.md` → 2장 구성, 90초 시연, 결선 Q&A.
- 협업 문서 초안·수정이 필요하면 `../doc-coauthoring/SKILL.md`를 필요한 범위로 활용한다.
- 파일 제작은 `../pptx/SKILL.md` 또는 `../docx/SKILL.md`를 읽는다.

제출용은 2장 이내. 표지·부록도 장수에 포함한다. 결선에서 더 많은 장을 허용하는지 운영진에게 확인한다.
1장: 사용자와 고통, 기존 방식의 한계, 왜 지금, 한 문장 해법.
2장: 실제 제품/결과, 증거와 측정 조건, 차별점, 첫 시장·과금 가설, 팀·데모 링크.
자료를 채우려고 근거 없는 시장 숫자·고객 인터뷰·매출·절감률을 만들지 않는다.
오늘 만든 MVP, 직접 확인한 것, 향후 계획을 분리한다.

산출물은 `artifacts/pitch/`에 PPTX와 미리보기, 선택한 PDF/DOCX를 저장한다.
소스와 재생성 명령, 사용한 실제 증거는 `docs/PITCH.md`에 기록한다.
PPTX는 렌더링해서 각 장을 열어 한글 폰트·줄바꿈·겹침·잘림·링크를 검증한다.
렌더러가 없으면 설치 가능 여부를 확인하고 미검증 상태를 명시한다. 구조 검사만으로 시각 검증 완료라고 쓰지 않는다.
90초 시연 대본과 10분 발표+Q&A 리허설 시간표를 함께 제공한다.
실제 제출 전 `demo-gate` 체크리스트와 사용자 최종 승인이 필요하다.
