# 해커톤 발표 흐름

원문: [Visual Storyteller](references/upstream.md). 출처·고정 커밋은 `docs/agency-sources.json`.
원문의 캠페인·SNS·멀티미디어 확장 대신 사용자 문제→실제 제품→변화라는 시각적 서사를 활용한다.

`docs/PITCH.md`와 실제 제품 화면을 확인한다. 화면이 없으면 빈 자리를 표시하고 가짜 제품을 실물처럼 보이지 않게 한다.
초기 제출은 최대 2장이다. 각 장에 읽는 사람이 기억할 문장 하나와 그것을 증명하는 시각 자료 하나를 둔다.
표지로 한 장을 소비하지 않는다. 캡처는 핵심 상호작용이 읽히도록 자르고, 장식보다 실제 결과를 크게 보여준다.
시장 추정·관찰·실측·예시는 시각적으로 구분한다. 차트에 출처와 측정 조건을 남긴다.
원문의 '50% 향상', '3배 효과' 같은 성공 지표는 실제 근거가 아니므로 복사하지 않는다.
프로젝터에서 읽을 글자 크기·대비와 한글 폰트를 확인하고 각 장을 렌더링해서 잘림을 수정한다.
실제 파일 제작은 `pptx` 스킬을 읽는다. 이 스킬만으로 PPTX 내보내기가 된다고 말하지 않는다.
90초 데모 대본과 전체 10분 안의 발표+Q&A 리허설을 준비한다. 현장의 시간 분할 지시를 우선한다.
한국어로 작성하며 새 영상·광고·애니메이션 제작으로 범위를 늘리지 않는다.
현재 대화에서 역할을 적용하고 에이전트를 자동으로 실행하지 않는다.
